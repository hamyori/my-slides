01

PÉRDIDA DE TRAZABILIDAD

Copias como proyecto_final_v2.zip no dicen quién cambió el código, cuándo lo hizo ni por qué.

No se puede auditar ni volver atrás con precisión.
02

SOBRESCRITURA SILENCIOSA

Dos personas editan el mismo archivo. La última en guardar puede borrar el trabajo de la primera.

El error aparece tarde, cuando ya es difícil reconstruirlo.
03

UN SOLO PUNTO DE FALLA

En modelos centralizados como SVN o CVS, el historial depende de un servidor único.

Si el servidor cae, todo el equipo queda detenido.

02 / ARQUITECTURA INTERNA

EL MODELO DE TRES ÁREAS Y EL GRAFO DE COMMITS

ZONA 1 · MUTABLE

WORKING DIRECTORY

  • Archivos locales en disco.
  • Aquí se edita, prueba y depura.
  • Estado: untracked / modified.
ZONA 2 · SELECCIÓN

STAGING AREA

  • Selección deliberada de cambios.
  • Permite preparar commits limpios.
  • Estado: staged.
ZONA 3 · INMUTABLE

REPOSITORIO LOCAL

  • Base de objetos dentro de .git/.
  • Cada commit es una instantánea.
  • Historial conectado como un DAG.

Presentación

    Tarjetas de repaso

    ¿Qué tres áreas componen el flujo local de Git?

    El directorio de trabajo, el área de preparación (index) y el repositorio local.

    ¿Qué diferencia a Git de GitHub?

    Git registra versiones de forma distribuida. GitHub aloja repositorios y facilita colaboración, revisión y automatización.

    ¿Cuáles son las cinco fases de Canny?

    Suavizado Gaussiano, cálculo del gradiente, supresión de no-máximos, doble umbral y seguimiento por histéresis.

    ¿Qué hace reproducible una ejecución entre equipos?

    Registrar el código, describir el entorno, fijar dependencias y comparar la misma prueba con la misma entrada.
